## Confirmed diagnosis

- The attached `invoice_Brij.pdf` was generated by **Microsoft Print to PDF**, on an **A4 page** (595.32 × 841.92 pt), and renders the invoice itself at only about **48mm wide** on the left side of the page.
- The print handler reads the configured bill printer paper size. When that setting is thermal (58mm/80mm), it passes the thermal size into `printIsolated()` even though this invoice is being sent through the browser’s A4 print dialog.
- Therefore thermal print CSS constrains `html/body` to 48mm or 72mm. Inside that already narrow document, Phase 65’s `min-width: 0` left column competes with the fixed 205px right column and collapses to character width.
- This is not only an address wrapping issue. The primary failure is the **wrong paper width being applied to an A4 browser invoice**, compounded by unsafe flex sizing.

## Implementation plan

1. **Force Lodge invoice / Draft Bill browser printing to A4**
   - In the folio print path, stop deriving the invoice page width from thermal printer configuration.
   - Always call the isolated browser print flow with A4 for this full invoice template, matching the current product decision that Lodge invoices use native browser printing.
   - Keep thermal settings and thermal bill/KOT paths unchanged.

2. **Make the premium header structurally print-safe**
   - Replace the collapsing `min-width: 0` behavior on the left header column with a readable print minimum.
   - Use explicit A4-safe column sizing: the left logo/address area gets the remaining space with a sensible minimum; the invoice metadata column gets a bounded fixed/basis width.
   - Allow normal word-level wrapping for address/contact text, while preventing arbitrary character-by-character wrapping.
   - Ensure logo dimensions, gap, and horizontal padding fit inside the 190mm A4 printable width.
   - Apply the same correction to both Tax Invoice and Draft Bill because both use this shared markup.

3. **Verify the actual print artifact, not only the screen preview**
   - Exercise the app’s real `printIsolated()` invoice path using browser print media and generate an actual A4 PDF artifact.
   - Render the generated PDF page to an image and inspect it directly for:
     - normal horizontal property name/address text,
     - intact Tax Invoice / Draft Bill metadata column,
     - no overlap or side clipping,
     - correct A4 printable width and pagination.
   - Also verify the configured thermal printer setting can no longer shrink Lodge invoice PDFs.

4. **Deliver visual proof**
   - Provide the rendered image from the fixed, generated PDF in the completion response.
   - State any remaining limitation explicitly: the sandbox cannot automate the native Windows **Microsoft Print to PDF** driver itself, but it can generate and inspect the same A4 browser print-media output that the driver receives. The supplied PDF metadata and rendering already confirm the Windows driver and the current 48mm layout failure.
